## 项目概述

本项目实现了一个**四步骤自动化脚本生成系统**，能够：

1. **自动检索**：从百度百科抓取硬核历史事实
2. **智能创作**：使用 Qwen-plus 生成 B 站风格的视频脚本
3. **素材匹配**：为脚本中的占位符匹配相关视频素材
4. **自动合成**：将文案与素材信息合并为最终脚本

**适用场景**：B 站 UP 主、内容创作者需要快速生成政经史类视频脚本的初稿。

## 核心功能

### ✅ 已实现功能

- ✅ **Step 1 - 搜研专家**：Qwen-plus 拆解关键词 → 百度百科抓取 → Qwen-plus 事实脱水
- ✅ **Step 2 - 金牌编剧**：Qwen-plus 生成 B 站风格脚本（含素材占位符）
- ✅ **Step 3 - 素材匹配**：提取占位符关键词，调用真实 B 站 API 搜索并匹配视频素材
- ✅ **Step 4 - 最终合成**：自动合并文案与素材信息
- ✅ **内容安全过滤**：自动检测并替换敏感词，确保符合 B 站审核要求
- ✅ **脚本导出**：自动保存为 Markdown 格式文件到 `output/` 目录
- ✅ **命令行界面**：Rich 库美化输出，清晰展示每一步结果
- ✅ **网页可视化界面**：Gradio 构建的简单 Web UI
- ✅ **异常回退机制**：API 失败时自动使用内置示例数据

### 🚧 待扩展功能

- ⏳ **批量处理**：支持一次处理多个选题
- ⏳ **批量处理**：支持一次处理多个选题
- ⏳ **多格式导出**：支持导出为 Word、PDF 等格式

### 各步骤详细说明

#### Step 1: 搜研专家 (`step1_research.py`)

**输入**：用户选题（字符串）

**处理流程**：

1. **关键词生成**（`_gen_baike_keywords`）
   - 调用 Qwen-plus，将选题拆解为 3-5 个适合百度百科检索的中文关键词
   - 例如：「麻生太郎家族发展史」→ `["麻生太郎", "麻生矿业", "麻生太吉"]`
   - **失败回退**：直接使用原选题作为关键词

2. **百度百科抓取**（`_fetch_baike_chunks`）
   - **优先方案（推荐）**：Bing 搜索聚合（纯 requests，最快最轻量）
     - 通过 Bing 搜索获取百度百科摘要，无需浏览器
     - 支持 VPN 环境（自动检测并切换 cn.bing.com / www.bing.com）
     - 信息密度高，搜索结果摘要就是事实浓缩
   - **备选方案**：DrissionPage（浏览器方案，反爬能力强）
     - 直接控制浏览器协议（CDP），无需下载 ChromeDriver
     - 天生具备极强的抗指纹检测能力
   - **回退方案**：requests 直接抓取百度百科
     - 对每个关键词请求 `https://baike.baidu.com/item/{关键词}`
     - 解析 HTML，提取摘要内容
   - 每个关键词最多抓取前 800 字符
   - **失败回退**：跳过该关键词，继续处理下一个

3. **事实脱水**（`_distill_facts_with_qwen`）
   - 将所有抓取的百科文本拼接，喂给 Qwen-plus
   - 要求模型输出 3-6 条硬核事实，格式为 JSON 数组
   - 每条事实包含：`title`（标题）、`summary`（摘要）、`sources`（来源）
   - **失败回退**：使用内置示例数据（`mock_research_facts_for_topic`）

**输出**：`ResearchResult`
```python
{
    topic: str,           # 用户输入的选题
    outline: List[str],   # 脚本大纲（4个部分）
    facts: List[FactItem] # 硬核事实清单
}
```

#### Step 2: 金牌编剧 (`step2_writer.py`)

**输入**：`ResearchResult`（Step 1 的输出）

**处理流程**：

1. **Prompt 构造**（`_build_prompt_for_qwen`）
   - 将事实清单格式化为提示词
   - 要求 Qwen-plus 生成 B 站风格脚本：幽默、有梗、逻辑清晰
   - 要求自动插入素材占位符：`[素材占位：关键词]`

2. **脚本生成**（`_write_script_with_qwen`）
   - 调用 Qwen-plus（`qwen-plus` 模型）
   - 生成完整脚本正文
   - 自动提取脚本中的占位符（正则匹配 `[素材占位：...]`）
   - **失败回退**：使用本地模板规则生成脚本（`_build_intro_section`、`_build_body_sections`、`_build_outro_section`）

**输出**：`ScriptDraft`
```python
{
    topic: str,                    # 选题
    title: str,                    # 脚本标题
    sections: List[ScriptSection], # 脚本章节（开场/正文/结尾）
    placeholders: List[str]        # 占位符列表
}
```

#### Step 3: 素材匹配 (`step3_materials.py`)

**输入**：`ScriptDraft`（Step 2 的输出）

**处理流程**：

1. **占位符提取与关键词优化**（`match_materials`）
   - 遍历脚本中的所有占位符
   - **使用 Qwen-plus 进行语义理解**，从占位符中提取精准的关键词
   - 优先提取核心实体（人名、地名、机构名、事件名、专有名词）
   - 去除修饰词和画面描述词，保留搜索友好的关键词
   - 如果 LLM 调用失败，降级到简单字符串提取

2. **B 站视频搜索**（使用真实 API）
   - 使用 `bilibili-api-python` 库调用 B 站搜索 API
   - 根据关键词搜索相关视频，按综合排序返回结果
   - 获取视频的 BV 号、标题、UP 主、播放量等信息

3. **播放链接获取**
   - 调用 B 站 API 获取视频的真实播放直链（支持 DURL 和 DASH 格式）
   - 返回网页链接和播放直链两种格式
   - 播放直链包含 Referer 防盗链，使用时需设置相应 Header

4. **素材匹配结果**
   - 为每个占位符匹配 1 个相关视频素材
   - 包含：占位符、关键词、视频标题、匹配理由、网页链接、播放直链

**输出**：`MaterialMatchResult`
```python
{
    topic: str,
    materials: List[MaterialItem]  # 每个占位符对应的素材
}
```

#### Step 4: 最终合成 (`step4_compose.py`)

**输入**：`ScriptDraft`（Step 2 输出）+ `MaterialMatchResult`（Step 3 输出）

**处理流程**：
1. **素材映射**（`compose_final_script`）
   - 将素材按占位符组织成映射表
   - 在脚本正文中查找占位符，插入对应的素材信息（标题、理由、链接）
2. **内容安全过滤**（集成在 `step4_compose.py` 中）
   - 自动检测标题、正文、素材标题和理由中的敏感词
   - 从 `config/sensitive_words.json`（优先）或 `config/sensitive_words.txt`（兼容）加载敏感词列表
   - 自动将敏感词替换为安全标记（默认 `***`）
   - 输出过滤后的安全脚本
3. **格式化输出**
   - 生成包含标题、正文、素材列表的完整脚本

**输出**：`FinalScript`（过滤后的安全脚本）

**注意事项**：
- 敏感词过滤在 Step 4 之后自动执行
- 如果发现敏感词，会在命令行/Web UI 中显示警告信息
- 敏感词列表可通过编辑 `config/sensitive_words.json` 自定义
- 如果敏感词文件不存在，系统会跳过过滤（不阻止运行）

**处理流程**：

1. **素材映射**（`compose_final_script`）
   - 将素材按占位符组织成映射表

2. **脚本合并**
   - 遍历脚本的每一行
   - 遇到占位符时，插入对应的素材信息（标题、理由、链接）
   - 格式化输出为 Markdown 文本

**输出**：`FinalScript`
```python
{
    topic: str,
    title: str,
    content: str,              # 最终脚本文本（Markdown）
    materials: List[MaterialItem]
}
```

## 快速开始

### 1. 环境要求

- **Python**：3.10 或更高版本
- **操作系统**：Windows / macOS / Linux

### 2. 安装依赖

```bash
# 克隆或下载项目后，进入项目目录
cd B站政经史“硬核”内容生成智能体

# 安装依赖
pip install -r requirements.txt
```

**关于百度百科抓取方案**：

本项目使用多种方案自动回退，优先级如下：

1. **Bing 搜索聚合**（推荐，默认使用）
   - 无需浏览器，纯 requests，速度最快
   - 支持 VPN 环境，自动切换域名
   - 无需额外配置

2. **DrissionPage**（备选，需要安装）
   - 安装：`pip install DrissionPage`
   - 无需 ChromeDriver，直接使用系统 Chrome 浏览器
   - 反爬能力强，适合需要浏览器渲染的场景

3. **requests**（回退方案）
   - 直接抓取百度百科，可能遇到 403 反爬虫拦截
   - 无需额外配置

**注意**：系统会自动按优先级尝试，如果某个方案失败会自动回退到下一个。

### 3. 配置 API Key

在项目根目录创建 `.env` 文件：

```bash
# .env

# 必需：阿里云百炼 API Key（用于 Qwen-plus）
DASHSCOPE_API_KEY=你的百炼APIKey

# 可选：B 站登录凭证（用于获取高清视频链接，不配置也可使用游客模式）
BILIBILI_SESSDATA=你的SESSDATA
BILIBILI_BUVID3=你的BUVID3
```

**获取 API Key**：
1. **DASHSCOPE_API_KEY**（必需）：
   - 注册并登录[阿里云百炼平台](https://dashscope.console.aliyun.com/)
   - 创建新的 API Key
   - 将 Key 填入 `.env` 文件

2. **B 站凭证**（可选）：
   - 如需使用登录状态获取高清视频链接，可在浏览器中登录 B 站后获取 Cookie
   - `SESSDATA` 和 `BUVID3` 可从浏览器开发者工具中获取
   - 不配置也可正常使用（游客模式，可能只能获取低清链接）

> **注意**：
> - 如果不配置 `DASHSCOPE_API_KEY`，系统会自动回退到内置示例数据，仍可正常运行，但无法使用 Qwen-plus 的真实能力
> - B 站 API 无需 API Key，可直接使用（游客模式）

1. 在「选题」输入框中填入主题
2. 点击「生成脚本」按钮
3. 等待处理完成（通常 10-30 秒，取决于网络和 API 响应速度）
4. 查看生成的脚本和素材列表
5. 脚本会自动保存到 `output/` 目录（Markdown 格式）

**注意事项**：
- 如果出现错误，两个输出框会显示友好的错误提示
- 如果未配置 API Key，系统会自动使用内置示例数据
- 网络不稳定时，可能会自动回退到示例数据

## 数据流与异常处理

### 数据流图

```
用户输入（字符串）
    ↓
ResearchResult（Step 1 输出）
    ↓
ScriptDraft（Step 2 输出）
    ↓
MaterialMatchResult（Step 3 输出）
    ↓
FinalScript（Step 4 输出）
    ↓
最终脚本文本（Markdown）
```

### 异常处理机制

系统设计了**多层回退机制**，确保在任何情况下都能正常运行：

#### Step 1 异常处理

| 异常类型 | 处理方式 |
|---------|---------|
| Qwen API Key 未配置 | 跳过关键词生成，直接使用原选题作为关键词 |
| Qwen API 调用失败 | 跳过关键词生成，直接使用原选题作为关键词 |
| 百度百科抓取失败 | 跳过该关键词，继续处理下一个 |
| 所有关键词都失败 | 使用内置示例数据（`mock_research_facts_for_topic`） |
| Qwen 事实脱水失败 | 使用内置示例数据 |

#### Step 2 异常处理

| 异常类型 | 处理方式 |
|---------|---------|
| Qwen API Key 未配置 | 使用本地模板规则生成脚本 |
| Qwen API 调用失败 | 使用本地模板规则生成脚本 |
| JSON 解析失败 | 使用本地模板规则生成脚本 |

#### Step 3 异常处理

| 异常类型 | 处理方式 |
|---------|---------|
| 占位符提取失败 | 生成默认占位符 |
| 关键词提取失败 | 使用默认关键词「历史纪录片」 |

#### Step 4 异常处理

| 异常类型 | 处理方式 |
|---------|---------|
| 脚本合并失败 | 返回原始脚本文本（不含素材链接） |

### 错误提示

### 核心文件说明

#### `agent_mvp/config.py`
- 管理 API Key 和模型配置
- 自动加载 `.env` 文件
- 提供 `CONFIG` 全局配置对象

#### `agent_mvp/data_types.py`
- 定义所有数据结构：
  - `FactItem`：硬核事实项
  - `ResearchResult`：Step 1 输出
  - `ScriptSection`：脚本章节
  - `ScriptDraft`：Step 2 输出
  - `MaterialItem`：素材项（包含网页链接和播放直链）
  - `MaterialMatchResult`：Step 3 输出
  - `FinalScript`：Step 4 输出

#### `agent_mvp/prompt_loader.py`
- 提示词加载器，统一管理所有模块的提示词
- 从 `config/prompt/` 目录下的 YAML 文件读取提示词
- 支持占位符格式化（`{topic}`, `{raw_text}` 等）

#### `config/prompt/` 目录
- 统一管理所有提示词文件（YAML 格式）
- 每个文件包含 `system` 和 `user` 两个字段
- 方便后续统一修改和维护，无需修改代码

#### `agent_mvp/step4_compose.py`
- Step 4 最终合成模块，包含内容安全过滤功能
- 自动检测标题、正文、素材标题和理由中的敏感词
- 从 `config/sensitive_words.json` 加载敏感词列表（支持多种 JSON 格式）
- 自动将敏感词替换为安全标记（默认 `***`）
- 支持严格模式（发现敏感词时抛出异常）和宽松模式（只替换）
- 可通过 `enable_safety_filter` 参数控制是否启用过滤

#### `config/sensitive_words.json`
- 敏感词列表文件（仅支持 JSON 格式），支持结构化存储
- 支持多种 JSON 格式：
  - 简单数组：`["敏感词1", "敏感词2"]`
  - 对象格式：`{"words": ["敏感词1", "敏感词2"]}`
  - 分类格式：`{"categories": {"政治敏感": ["词1"], "历史不当": ["词2"]}}`
  - 扁平结构：`{"政治": ["词1"], "历史": ["词2"]}`
- 匹配时不区分大小写
- 如果文件不存在或格式错误，系统会跳过过滤（不阻止运行）
- 建议根据 B 站社区规范和审核规则定期更新

#### `main.py`
- 提供两种运行模式：
  - `run_pipeline_cli`：命令行模式（Rich 美化输出）
  - `run_pipeline_ui`：网页界面模式（Gradio）
  - `launch_web`：启动 Gradio 服务器

## 常见问题

### Q1: 为什么生成速度很慢？

**可能原因**：
1. **网络延迟**：Qwen API 和百度百科都需要网络请求
2. **VPN 影响**：如果使用 VPN，可能会增加延迟
3. **API 限流**：Qwen API 可能有速率限制

**优化建议**：
- 确保网络连接稳定
- 如果不需要真实数据，可以不配置 API Key，使用内置示例数据（几乎秒出）

### Q2: 如何提高生成质量？

**建议**：
1. **配置 API Key**：确保 `.env` 中配置了有效的 `DASHSCOPE_API_KEY`
2. **优化选题**：选题越具体、越明确，生成效果越好
3. **调整 Prompt**：可以修改 `step2_writer.py` 中的 prompt 模板

### Q3: 为什么百度百科抓取失败？

**可能原因**：
1. **网络问题**：无法访问百度百科或 Bing 搜索
2. **关键词不匹配**：百度百科中没有对应词条
3. **反爬虫机制**：百度百科可能有反爬虫限制（403 错误）

**处理方式**：
- **推荐**：使用默认的 Bing 搜索聚合方案（无需配置，最快最轻量）
- 如果遇到反爬虫问题，可以安装 DrissionPage：`pip install DrissionPage`（无需 ChromeDriver）
- 系统会自动跳过失败的关键词，继续处理下一个
- 如果所有关键词都失败，会返回空数据（便于测试真实效果）

**DrissionPage 配置（可选）**：
1. 安装：`pip install DrissionPage`
2. 确保系统已安装 Chrome 浏览器
3. 无需下载 ChromeDriver，DrissionPage 会自动使用系统 Chrome
4. 运行程序时，如果 Bing 搜索失败，系统会自动尝试 DrissionPage 方案

### Q4: Step 3 使用的 B 站 API 是什么？

**当前状态**：Step 3 已接入真实 B 站 API

**技术实现**：
1. 使用 `bilibili-api-python` 库（社区维护，内置 WBI 签名算法）
2. 调用 B 站搜索 API 搜索相关视频
3. 获取视频的真实播放直链（支持 DURL 和 DASH 格式）

**配置说明**（可选）：
- 如需使用登录状态（获取高清链接），可在 `.env` 文件中配置：
  ```bash
  BILIBILI_SESSDATA=你的SESSDATA
  BILIBILI_BUVID3=你的BUVID3
  ```
- 不配置也可正常使用（游客模式，可能只能获取低清链接）

**参考文档**：
- [bilibili-api-python 文档](https://github.com/Nemo2011/bilibili-api)
- [Bilibili API 收集](https://github.com/SocialSisterYi/bilibili-API-collect)

### Q5: 网页界面无法启动（502 错误）？

**可能原因**：
1. **端口被占用**：7860 端口已被其他程序使用
2. **代理冲突**：系统代理可能拦截了本地请求

**解决方案**：
- 代码已自动处理代理问题，如果仍有问题，检查系统代理设置
- 尝试更换端口：修改 `main.py` 中的 `demo.launch(server_port=7861)`

### Q6: VS Code 提示「无法解析导入」？

**原因**：VS Code 使用的 Python 解释器与安装依赖的解释器不一致

**解决方案**：
1. 在 VS Code 右下角选择正确的 Python 解释器
2. 确保该解释器已安装所有依赖：`pip install -r requirements.txt`
